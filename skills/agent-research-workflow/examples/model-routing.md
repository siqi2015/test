# 模型路由案例

这是用户提供的背景和建议工作，不是已完成的实验报告；信息未经独立核验。用户提供的防污染报告用于说明表达偏好，不作为新增已验证结果。

## 目标

研究具有普适性或泛化性的模型路由。当前优先关注正确率，再研究让 weak 承担更多任务的可能性。正确率容忍度未量化，先报告成功率和真实成本的取舍。

## 当前起点

用户使用 Multi-SWE-Bench 的 Jackson 三仓 43 道 Java 修复题，strong 为 dsv4.1flash，weak 为 qwen9B。名称按用户提供记录，不推断服务或版本。模型、角色、任务集、环境和成本均可调整。

用户反馈配置与评测流程一致，但路径、实际测试轮数和成败有波动；已记录完整轨迹、效果、token、费用和耗时。当前切档 uncached token 及费用较大，现有 router 效果不及全程 strong。

## 开放问题

研究哪些信息与机制有助于选模型。初始选档、早期选档、事件触发切换和多模型等均可考虑，早期一次切换后锁档只是候选。

若研究早期选档，strong 和 weak 起步都作为候选，不预设优劣。还要定义决策点及“weak 完成”的统计方式，不凭单次成败形成硬标签。

## 建议工作

先复用已有数据检查记录和统计定义，分析固定模型及现有 router 的效果、成本、失败与波动。分清局部观察、解释和需新实验回答的问题。

保留机制不同的方向，说明假设及验证方法。按信息价值选择本轮行动，不把当前配置变成永久边界。

若研究早期状态切档，可从相同会话、工作区和工具状态分别续跑两模型，计入接管开销。strong 从头做题与接管 weak 的状态不同，不能直接替代分支结果。

评估保留同题关联，避免同题轨迹跨训练与测试。说明当前任务集能支持的范围；跨模型和跨任务泛化需要相应证据。上述建议尚未执行。
