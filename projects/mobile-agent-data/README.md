**1. 当前目标与分工**

当前首先交付强教师 trace 的离线序列蒸馏数据：保留真实输入、思考、动作和观察，优先按一次模型请求／输出建立训练样本，验证同事的训练器能读取且监督到预期输出。任务结果未评估不阻塞 demo，不能补写成功标签。具体模型和框架未知时先保留中立表示，交付前通过目标模板验收。训练基础设施与训练运行仍由同事负责。

长期业务方向继续包含“记忆是否被正确理解和使用”的评测与训练数据。第 2–8 节保留此前推荐业务的说明和方案，其既有资料不能当作本批新 trace，也不把此前“先校准质量评估”的顺序作为本次 demo 前提。当前交付步骤以首版交付方案为准。

用户进一步明确评估系统有两个作用：指导训练数据筛选／合成，以及判断优化后的 Agent 是否改善执行效果。两者共享正确性标准；具体评测案例、数据用途与独立校验机制需要区分。该评估系统是当前核心设计之一。

此前脱敏材料及数据侧补充将那批业务任务明确为上游推荐生成：读取记忆、当前情境、能力说明及历史推荐池，生成完整卡片集合，包含逐卡引导语、推荐项展示文案和交接给下游的任务描述。历史推荐池附带曝光／点击计数，不能当作已完成的执行产物或用户明确偏好。推荐内容有价值、交接描述足够明确与下游真正执行成功是不同检查对象；那批数据不含下游执行结果或真实满意反馈。该业务路径继续保留，不代替当前教师 trace 到学生 SFT 的交付目标。

**2. 先评估四种记忆使用能力**

| 能力 | 想知道什么 | 典型错误 |
| --- | --- | --- |
| 判断相关性 | 哪些记忆能支持当前服务，哪些无关 | 忽略有关偏好，或强行使用无关记忆 |
| 理解含义与适用范围 | 是稳定偏好、临时要求、过去事件，还是不确定推断 | 把一次行为当长期偏好，把工作日要求套到所有场景 |
| 处理变化和冲突 | 哪条记录仍有效，哪些有条件、已完成或被明确更新 | 使用已失效信息；机械认为时间最新的一条永远正确 |
| 转化为恰当服务 | 内容、动作、时间是否符合记忆支持的需求 | 引用了正确记忆却作出不合适的推荐、重复推送或时机错误 |

先把一份候选记忆直接放入样例，评估“看到了以后是否会用”。后续取得真实接口后，再区分完整记忆库里有无相关信息、检索是否找出、模型最终是否看到以及看到后是否用对。当前给定记忆的结果不能当作端到端检索效果。

记忆提取、写入、更新和删除也可能影响结果；当前保留为待核验环节，不在没有实现依据时自行增加整套记忆系统建设。

输入中的显式事实、模型归纳、场景索引与历史推荐需区分来源和可靠程度。模型推断不自动等于用户明确偏好，索引不等于已加载的事实，过去推荐过不等于已经执行。历史推荐、曝光、点击、明确接受／拒绝、实际完成分别记录；缺失计数不填零，未点击不自动等于拒绝。主动帮助可以由已知事实推导，不要求凭空新增事实。

**3. 一条样例先理解为五个部分**

| 部分 | 需要写清楚的内容 |
| --- | --- |
| 当前情境 | agent 在什么时间、准备提供什么服务，当时可见哪些信息 |
| 可用记忆 | 每条记忆的内容、ID、来源和适用时间；事实、明确偏好和推断要能区分 |
| 候选表现 | 保留完整推荐集合及其中的卡片、推荐项、引导语和交接描述；实际或候选动作／回复的执行状态要明确 |
| 判断依据 | 哪些记忆相关，哪些选择可接受，哪些行为违反约束，依据来自哪里 |
| 来源与状态 | 真实记录／公开转换／合成，案例与卡片／推荐项的父子关联、用途切分、审核状态及生成版本 |

标签侧的参考判断不能泄漏给被评测模型。内部推理、检索过程和执行结果未提供时，不补造。候选表现没有运行证据时标为生成候选，不能写成真实 trace。

具体虚构例子见入门文档。初期允许表格人工查看、JSONL 程序读取；不需要先设计庞大 schema。

**4. 当前只沿一条数据流程推进**

```text
明确“怎样才算用对记忆”
  → 建立可逐条核验的种子案例，并划分开发／训练来源与独立评测来源
  → 收集或生成候选表现
  → 筛选：检查依据、行为和记录是否合格
  → 合成：围绕覆盖缺口构造记忆与情境变体
  → 再核验，形成有版本的数据包
  → 训练同事使用，双方按固定评测样例回查错误
```

已完整读取用户提供的脱敏技术摘要及数据侧补充，包含输入输出结构、不同评价对象、统一量程、自动化评测说明、统计和合成骨架；尚未取得原始逐条样本。输出边界和逐卡引导语／逐推荐项／整组的评价层级已得到数据侧说明；完整分档、聚合和实际评审输入仍待核验。统计未独立复算，归因也不自动成立。下游执行不在当前数据范围内，不将该缺口算作推荐样例的失败。

**5. 筛选与合成各负责什么**

筛选是判断已有或已生成的样例是否可用、适合什么用途，并记录原因。至少检查：决策输入及缺失状态可解释；当前判断依赖的记忆当时可用；行为符合记忆含义和约束；未把猜测写成用户事实；输出和依据不矛盾。记忆块为空不自动淘汰。原评分和理由先作定位线索，随后分为可保留示范、输入可用但输出需修复、证据不足待复核；记录损坏单独标明。合格后还需按来源去重和补足能力覆盖。

合成是补齐当前缺少的学习场景。先围绕同一案例做可解释的变化：更新有效偏好、增加已完成记录、移除关键证据、加入无关干扰。变化是否应改变行为要预先说明，再生成候选并核验。必要时重新定义标签，不能沿用变更前的答案。

当前建议先做三类操作：保持输入不变，修复证据明确的错误输出；改变关键记忆及其依赖字段，核验行为是否随条件合理改变；结合背景事实、有效偏好和可用能力，合成有依据的主动服务提议，避免数据只教少推荐。完整构造演示见 [入门流程第 4.1–4.2 节](architecture-and-technical-options.md)：旧旅行取消与报告需求的修复、新目的地的行为变化，以及会议背景下主动准备提纲。全部为虚构设计，未筛选真实业务样本。

筛选合格后才进入相应训练视图。失败和被排除记录保留，可用于错误分析或经核验的比较样本；不能默认全部作为正面示范。合成标签在虚构设定内成立，不等于真实用户满意度。

**6. 给训练同事的三类交付**

| 交付物 | 内容 | 用途边界 |
| --- | --- | --- |
| 独立评测集 | 记忆、情境、检查标准、可接受结果与来源 | 比较训练前后；最终测试来源不用于合成训练数据或调规则 |
| SFT 示范数据 | 记忆、情境和推荐历史 → 经核验的完整推荐集合，保留依据与审核信息 | 确认模型输出与后加评分字段的边界；不默认把评语、分数或否决标注作为生成目标，原始记录不被训练格式覆盖 |
| RL 候选任务与评价规格 | 初始记忆／情境、推荐决策目标、可检查条件与失败定义 | 推荐层优化可基于重新生成的集合和校准后的评价，不必先接下游执行；采样与奖励接线由训练同事负责，当前尚未形成可运行任务或真实收益奖励 |

另附数据版本、来源比例、能力覆盖、筛选原因与已知局限。偏好对有明确需要且能构造可比候选时再提供，不作为首批必须产物。

**7. 起步技术与判断方法**

第一版使用可人工查看的表格、JSONL 和简单 Python 处理即可。先把每个案例的可接受结果、关键约束和证据要求写清，再让代码检查确定性条件、模型辅助检查语义。逐项返回通过／失败／证据不足／不适用及事件引用；宽泛标签仅用于汇总。人工核验样例用于校准评估器，模型自评分不能单独证明正确。

引用了记忆 ID 不等于真正用对：应同时看行为是否符合依据，关键记忆变化后是否合理调整，无关信息变化时是否保持稳定。结果、过程约束与错误位置分别报告；主动服务还需同时检查遗漏帮助、不必要介入、时机和重复。标签和自动根因诊断均需核验。具体方法比较、判定示例与校准步骤见 [评估系统设计](evaluation-design.md)。

初期评测开发集用于校准规则和生成策略；独立测试集用于阶段评价。共享原始故事、用户历史或变体家族的样例不要拆到训练和测试两侧。保存全部允许保留的原始记录，统计说明分母和排除原因。

**8. 最容易上手的第一阶段**

现有材料已足够推进推荐层评测规格草案：以完整集合为主单位，分别检查推荐项、逐卡引导语和集合约束，评价依据有效性、任务交接及覆盖／去重。数据侧已说明相关结果维度指向拟交付任务的形态，不能解释为实际执行收益；具体分档、被评字段、聚合、门控及静默协议仍待核验。历史重复、明确拒绝和曝光未点击分开检查，不按总分或点击缺失直接划分训练好坏样本。详细方法见评估设计第 13 节，业务数值仅本地记录。

后续样例表优先吸收允许描述且能核验的业务案例；材料不足时，以“夜间为用户准备阅读推荐”等虚构情境补充演示，明确区分来源。覆盖正常偏好使用、条件适用、明确需求变更、历史重复、缺少依据与无关干扰。有可靠完成记录的情况可作为额外合成变体，但不能由推荐或点击记录推导。约 20 条仍只是便于逐条核验的候选起步规模，可根据分歧和覆盖调整；先确认接受或排除的理由，再实现读写、检查和分流。

近期建议先验证一个具体机制：用户已明确变更或拒绝旧需求时，推荐是否仍沿用旧画像。配套保持旧需求有效、增加无关信息等对照，避免只学习“一律不推荐”。可靠评价建立后，再用核验过的反馈修复候选并重新检查整个集合，形成示范或同输入偏好对；当前不直接优化原评审分数。

先检查评估器能否区分正确、错误和证据不足的样例，并观察错误放行与有效解法误杀。接着只做一类受控变体，例如“需求仍有效／已明确取消”，检查生成后答案是否随条件正确改变；以“历史推荐但反馈未知”作对照，避免把非点击学成拒绝。标准能稳定使用后再扩展场景和数量，并与训练同事做小批数据交付。新旧模型在独立输入上重新生成完整集合，可支持推荐能力比较；下游执行收益和真实满意度仍需相应证据，筛选通过率、数据量或旧输出重评不能替代。

这条路线可借鉴用户熟悉的 skill 自演进流程：收集案例、识别不足、生成候选、验证保留。这里沉淀的是有依据的样例和检查标准，后续由训练同事用于模型能力增强。
