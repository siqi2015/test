# 数据与验证

## 先检查现有记录

研究数据完整性优先于采集速度。已有设施完整时直接复用；有实际缺口再补，不为遵循规范重搭系统。

结合研究问题明确需要记录哪些可观测数据。不为省时自行截断轨迹、只留成功记录或汇总，也不擅自把完整采集改成抽样。完整性与新增实验数量分别安排。

记录实际可获取、允许保存的信息。服务未返回的内部过程不能补造，凭据等秘密不写入日志。无法取得的字段标明原因。

## 一次运行应能回查

按研究需要检查以下内容能否关联。字段名和保存方式适配已有项目，不强制格式。

| 内容 | 应能回答的问题 |
| --- | --- |
| 任务、运行、配置及分支标识 | 哪次尝试？哪些记录属于同一任务或前缀？ |
| 数据来源、代码版本、初始状态与改动 | 从什么条件开始，执行中改了什么？ |
| 模型、提示词、采样、工具、资源与评测配置 | 条件是什么，哪些未知或不能固定？ |
| 实际请求和响应、工具输入输出、可得中间状态 | 发生过什么，路径怎样分叉？ |
| 最终产物、测试证据、终止原因 | 成败依据是什么，是超时、服务异常还是其他终态？ |
| 原始 usage、cached／uncached token、费用来源、时间记录 | 消耗是什么，哪些是估算？ |
| 指标定义、处理程序版本、筛选说明 | 怎样汇总，能否重算？ |

原始记录与清洗、重标、汇总结果分开保存，后者不覆盖前者。重要结论能追到具体运行和评测证据。失败、中断也保留，缺失不静默删除。

统计说明分母及排除理由。没有结果不直接等于算法失败，运行异常也不悄悄排除；保留总尝试数及各状态，按研究问题说明统计方式。

## 随机结果

固定或记录运行前条件，如初始代码、资源上限和评测流程。实际步骤数、路径和耗时可以是研究结果，不必强行相同。

同题成败翻转时，区分评测波动与轨迹差异。可先查同一最终产物重复评测是否一致，再分析轨迹。一次对照只支持相应范围的观察。

不把一次 strong 成功、weak 失败直接作为确定路由标签。估计什么条件下哪种选择更有利，并说明数据不足。少量重复能发现波动，不能自动得到可靠真值。

同题多次运行不等于更多独立题目。训练、选择方法和测试时，把同题相关轨迹、分支与前缀放同一侧，避免泄漏。验证范围对应所声称的泛化范围。

## 公平比较与成本

记录方案实际获得的资源和信息。探测、评估模型、上下文回放、重试等计入相应策略的真实成本。

效果、费用、token 和耗时按问题分别报告，不擅自合成单一分数。跨模型的总 token 不自动等同费用；保留原始 token、缓存信息、价格来源和估算方法。

区分算法耗时、数据采集处理及其他等待，避免把记录开销误归因算法。完整采集优先不意味着省略耗时指标。

价格或环境可变时，按需要做有依据的情景分析，说明结论何时变化。情景结果标为估计，不写成实测。

## 从观察到结论

按主张选择对照、消融、留出数据、独立复现、人工核验或可执行校验。另一位模型同意不能替代任务结果和原始证据。

说明支持什么、尚不能说明什么、哪些证据会改变判断。标签、评测或采集有缺口时，可以给有限观察，不给超出范围的结论。假设未获支持和证据不足也是有效交付。
