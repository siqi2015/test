# 主动服务 agent：agentic RL／SFT 研究与工程

持续维护的项目说明，最近更新于 2026-11-03（Asia/Shanghai）。当前阶段：背景梳理与方案讨论。用户明确的背景与协作要求已记录；本文中的技术路线、接口和实验安排仍为建议，尚未开始数据处理、算法实验或训练。

**1. 项目目标与当前依据**

核心目标是通过监督微调（SFT）与 agentic reinforcement learning（agentic RL，智能体强化学习）研究开发，提升合作方“主动服务 agent”的实际能力。任务与执行轨迹（trace）的筛选、合成和质量验证，是支撑该目标的首批工作；后续还需要与训练、环境和能力评测衔接。

用户在背景补充中明确了以下情况。这些属于用户提供的项目事实，尚未通过代码或运行记录独立核验：

1. 合作方负责智能手机助手“主动服务 agent”本体，我们负责后续 agentic RL／SFT 研究开发。
2. agent 当前基于深度修改的 OpenClaw，内部已实现一些 skill；具体实现代码尚未取得。
3. 产品希望主动发现用户需求并完成任务，包括夜间的内容挖掘与推送等场景。
4. 产品对标对象按用户描述记录为 Meta 的“muse”。具体产品版本、参考材料与对标能力尚未明确，不能据此推断本项目架构或训练方法。

因此，研究边界更新为“如何训练并评估现有主动服务 agent”。训练侧需要定义的数据、环境和模型接口可以与合作方协作，但当前不把重建手机助手、执行系统或产品功能列为本方实现范围。

用户已明确：研究与工程同时需要；先初始化工作区、加载研究 skill 并讨论第一版理解；后续逐步补充信息，并持续将讨论与调整维护到相关文档。因此当前交付是项目入口、工作规范和分析草稿，后续按讨论结果推进实现与实验，并同步维护结论与依据。

**2. 核心问题：什么数据能帮助 agent 学会什么**

主动服务需要同时研究“是否值得做、何时做、做什么”和“怎样完成”。建议先按以下能力理解数据与训练目标，实际优先级由已有问题和证据决定：

| 能力 | 需要判断什么 | 训练／评测需要的依据 |
| --- | --- | --- |
| 需求发现 | 当前上下文是否支持某个潜在需求，是否值得继续探索 | 决策时可用的用户上下文、历史和记忆，以及需求依据；不能靠事后反馈补写当时已知信息 |
| 主动服务决策 | 现在行动、后台准备、等待、询问用户，还是暂不行动 | 候选机会、时间、用户偏好与约束；需要能够研究适当克制和遗漏机会 |
| 任务执行 | 如何规划、调用已有 skill／工具、检查结果与恢复失败 | 完整执行过程和环境结果；具体训练动作空间取决于合作方接口 |
| 内容选择与交付 | 内容是否正确、有用、及时且避免重复，是否应推送、何时推送 | 内容来源与证据、生成／展示时间、交付渠道和真实反馈 |

夜间内容挖掘与向用户推送可能发生在不同时间，也可能由不同机制决定，目前不能假定两者同时发生。后台准备成功、内容有价值、推送时机合适需要分别评估。后续可研究跨夜间作业和后续用户交互的反馈关联，但具体奖励时间范围尚未确定。

原有任务、执行与步骤表示继续保留，并向前补充主动服务的机会／决策上下文：

| 对象 | 描述的内容 | 为什么需要 |
| --- | --- | --- |
| 机会／决策上下文 | 某个时刻可见的信号、候选需求及采取或暂不采取行动的记录 | 主动任务可能由 agent 产生；仅记录执行过的任务，会漏掉触发判断和暂不行动的样本 |
| 任务 task | 用户目标、成功条件、初始环境及必要上下文 | 解释 agent 要完成什么，并支撑重复执行 |
| 一次尝试 episode | 某个 agent 在具体配置下对任务的一次执行，包含终止原因 | 同一任务可能有多次成功、失败或中断；不能把一次成败当成任务的确定属性 |
| 事件／步骤 event | 观测、动作、工具请求与响应、状态变化和时间关系 | 支撑步骤学习、错误定位与过程验证；异步工具或子任务需要关联关系，不能只按日志行拼接 |

“高质量”应分解为记录完整性、执行有效性、结果可信度、行为质量与覆盖度。成功但冗余、失败但有高价值恢复过程、任务正确却记录缺失，都应分别表达。用于训练的筛选视图与保留完整研究数据是两件事：被排除的数据仍应能回查原因。

需要补充关联推送是否实际展示、反馈发生时间与观察窗口。没有记录某个机会，不等于 agent 当时决定不行动；用户未点击或未回复，也不能直接标为需求不存在或任务失败。若当前日志只包含被选择的候选，未选择候选的价值通常无法直接从这些日志得出。

**3. SFT 与 RL 的数据需求应分别定义**

| 用途 | 主要产物 | 关键条件 |
| --- | --- | --- |
| SFT | 在模型当时可见的上下文下，经过验证的 agent 动作或回复示范；可按整条轨迹或有效片段导出 | 明确训练角色与 loss mask；未来观测不能进入当前决策输入；失败尝试中的正确片段需有证据支持 |
| 偏好学习／过程评价（可选） | 可比上下文下的候选动作或轨迹、偏好或过程标签及其依据 | 不把不同初始条件、资源预算下的结果强行配对；标签保留不确定性 |
| 在线 agentic RL | 任务与初始状态、可执行环境接口、结束条件、奖励／结果验证器，以及新采样的 rollout 记录 | 环境能够执行，且重置、状态准备与奖励计算可信；历史 trace 可用于构建任务和校准验证器 |
| 离线 RL（候选） | 已记录的状态／观测、动作、奖励、终止及行为策略相关信息 | 单独评估部分可观测性、覆盖不足和策略分布差异；静态 trace 不自动满足某种离线算法的假设 |
| 独立评测 | 留出的任务、环境条件、结果验证与运行记录 | 与训练数据及其合成后代隔离，支撑能力与泛化判断 |

SFT 的目标监督信息可以来自事后验证，但决策输入必须忠实于当时的信息。工具返回、截图或环境状态可作为后续上下文，不能无区别地作为 agent 应生成的内容。内部推理未由数据源提供时标记缺失；事后生成的解释需要单独标为合成，不能伪装成原始过程。

在本项目中，SFT 候选样本还包括有依据的需求发现、合适的暂不行动／延后决策、skill 选择、内容组织和结果验证。RL 可研究执行成功、服务价值、时机与成本之间的关系，但先分别定义和检查这些信号，不直接固定加权奖励。点击、停留等交互指标只能作为可能的代理信号，不能自动等同于满足用户需求。

能训练什么取决于模型和系统接口：可替换／微调的模型是哪一个，哪些决策由模型输出，哪些由固定规则或 skill 脚本控制，是否能重新采样执行，以及训练后的模型能否接回原系统。现有 skill 的存在不等于其内部所有行为都可被 RL／SFT 优化。在线训练、参数访问和奖励接入能力均待核验。

**4. 建议的数据处理结构**

建议从一条可重跑的小流程开始，接口稳定后再按规模拆分。JSONL／Parquet、数据库、对象存储和调度系统的选择取决于数据类型、体量与复用需求，目前不固定技术栈。

```text
原始上下文、候选需求、任务、trace、反馈与附件
  → 接入与标准化（保留原始来源、缺失项和异常）
  → 完整性检查、敏感信息处理、去重与关联
  → 任务／来源家族分组及训练、验证、测试切分
  → 质量判断、分层筛选与采样
  → 在获准的训练来源上合成候选
  → 执行／证据验证、重标与质量复查
  → SFT 导出／RL 任务与环境包／独立评测集
  → 训练和评测结果回流，修订数据策略
```

只有需要合成的分支进入候选生成，经过验证的真实数据可以直接导出。新生成的数据继承来源家族和切分归属，并再次检查跨集合近重复；不能借助测试内容生成训练样本。

建议的逻辑模块是接入器、标准数据表示、验证器、筛选／采样策略、合成策略和训练导出器。研究方法通过配置或小模块替换，避免质量判断、合成提示词与训练格式互相绑定。

标准表示至少需要能够关联：任务和运行 ID、来源与父样本、事件顺序与因果关系、实际观测与动作、原始附件引用、环境与模型／工具版本、终止状态、结果证据、评估方法版本、筛选原因、切分归属和派生历史。先从真实样本反推字段；无法取得的数据写明缺失原因，不要求先填满理想 schema。

主动服务场景还需检查决策时刻、当时可读记忆／上下文的版本、候选需求及其来源、触发机制、未行动／延后记录、skill 版本，以及夜间作业到后续交付与反馈的关联。这里只列候选记录需求，不假设合作方已经提供这些字段。反馈可用于事后标签，但不能泄漏到更早决策的输入。

原始层、标准化层和训练视图分别保存。公开 Git 仓库保存规范与代码；个人 trace、截图和日志的存储位置及访问范围另行确定。允许保存的原始证据应完整保留，凭据等秘密不进入日志；脱敏后的文本、截图和结构化状态还要保持相互一致。

**5. 筛选需要比较的研究路线**

| 候选路线 | 工作机制与价值 | 主要依赖／未知 | 哪种观察会改变选择 |
| --- | --- | --- | --- |
| 规则与结果验证 | 检查记录结构、动作合法性、工具响应与真实结果证据；作为可解释基线 | 规则能否覆盖主要错误，成功条件是否可验证 | 大量有效行为被误删，或规则通过的轨迹仍有系统性错误 |
| 模型辅助评价 | 结合任务上下文评价行为、错误类型和恢复过程，补充难以写规则的质量判断 | 与人工／环境证据的一致性、偏差和评估成本 | 评价器偏好文风或表面“顺利”，却无法识别执行错误 |
| 覆盖度与信息价值采样 | 按任务族、工具、状态、失败类型、难度或学习价值保留不同样本 | 特征如何定义，罕见但有用的数据如何识别 | 纯高分筛选降低长尾覆盖或恢复能力，此路线可能更合适 |
| 根据训练反馈选数 | 利用学习进展、模型分歧或下游验证反馈更新样本权重 | 需要可重复训练／验证回路，计算代价更高 | 数据侧分数提升不能带来下游能力提升，需要检验反馈式策略 |

这些方向可以组合，但需要通过对照分辨各自作用。先实现规则基线是为了取得可检查的参照，不能据此认定规则已经足够，也不能将当前难以实现的方向判为无效。质量、难度和样本价值应分开观察，不预设一个万能总分。

主动服务的筛选还需分别检查“任务执行成功”和“这项服务值得提供”。暂不推送、延后行动和重复内容被正确抑制的记录可能具有训练价值；不能预设执行更多任务或推送更多内容就是更优行为。

**6. 合成应区分任务、轨迹、标签与环境状态**

| 候选路线 | 可以增加什么 | 验证要求 |
| --- | --- | --- |
| 任务改写与条件变体 | 目标表达、参数、约束与组合任务的覆盖 | 保留可执行性与明确成功条件；语义近重复仍属同一来源家族 |
| 环境内重新采样 | 利用同一或不同策略生成实际执行轨迹 | 保存全部尝试，记录初始状态、策略和结果；成本较高但执行证据更直接 |
| 失败恢复与分叉探索 | 从失败点或共同前缀尝试不同动作，形成恢复示范或可比候选 | 需要恢复可比状态；保留原失败轨迹，修复结果单独记录与验证 |
| 轨迹重标、片段提取与偏好构造 | 从已有尝试提取可验证片段、过程标签或比较样本 | 标签必须能回到证据，不能将未验证片段包装为成功示范 |
| 模型生成轨迹／模拟器／世界模型 | 在执行环境稀缺时探索更广状态和行为 | 与真实环境校准，隔离低置信样本；语言生成的工具成功和屏幕变化不算真实执行证据 |

合成策略应对准已发现的数据缺口，例如某类工具失败后缺少恢复样本。是否增加训练价值，需要比较“真实数据”“筛选后的真实数据”和“加入不同合成数据”后的表现；规模扩大本身不证明质量或能力提高。

主动服务的候选合成方向还包括：在受控上下文中改变时间、已有内容、需求是否已完成或用户明确偏好，研究应行动、延后或不行动的差异。合成用户画像、模拟反馈和需求标签都必须标明来源及假设；模拟用户同意或点击不能作为真实用户价值证据，也不能替代真实反馈上的校准。

**7. 怎样判断研究和工程分别取得进展**

工程验证回答流程能否可靠工作：数据能否解析与关联、异常是否保留、派生结果能否追溯、重复运行是否符合约定、训练导出是否符合目标接口。小规模演示跑通仅支持这类结论。

研究验证回答数据策略是否改善目标能力。建议从三层证据逐步建立：

1. 数据层：总尝试数和各种终态、缺失与重复情况、筛选保留／排除理由、任务覆盖、合成验证通过情况。统计需说明分母，异常不能静默排除。
2. 标签与验证器层：在有真实结果证据或人工核验的子集上，检查错误保留、有效样本误删和评价不一致；证据本身也可能有缺陷。
3. 下游能力层：在独立任务和环境条件下比较需求判断、任务成功、恢复行为、内容有效性、交付时机与成本；按任务族报告差异和随机波动。另行检查重复／无关服务、用户明确拒绝或纠正等现象；具体指标取决于可观测证据，不预设点击率为核心目标。

建议的对照起点是相同基础完整性／隐私处理后的原始可用数据、规则筛选、增强筛选，以及在选定真实数据上加入合成数据。按研究问题控制或分别报告数据量、训练 token、采样／评价／生成计算预算，避免将额外数据或计算的收益归因于策略本身。不同筛选结果可分别比较等预算效益和保留全部有效数据的实际收益。

训练／测试切分按任务家族、共享前缀、用户来源、应用和时间等相关性确定，不随机拆散同题轨迹或合成后代。具体选择取决于声称哪种泛化能力。随机策略用重复运行观察分布，重复次数依据波动和资源讨论，不预设整个课题的次数或效果阈值。

主动服务还需要区分同一用户未来时段的适应能力与对新用户的泛化能力。共享记忆、同一夜间作业产物及后续推送反馈可能连接多个 session，切分时需一起检查。比较训练前后模型时，记录或控制 skill、触发规则、内容来源与执行环境版本，避免把合作方系统变更误归因为训练收益。

**8. 预研与工程的建议推进顺序**

| 阶段（建议） | 研究要回答的问题 | 工程产物 | 进入下一步需要的证据 |
| --- | --- | --- | --- |
| 真实材料梳理 | 主动服务如何触发，哪些模型决策可训练，任务与反馈如何关联 | 合作方接口盘点、小批样本解析与缺失报告 | 能追溯一次服务过程，知道现有数据支持哪些训练与评测用途 |
| 最小流程 | 什么可以可靠筛选，什么必须标为未知 | 标准表示、规则验证、筛选报告及一种目标导出 | 能重跑并回查筛选原因，人工／环境证据核验关键行为 |
| 方法探索 | 增强筛选或某种合成方式是否解决已知缺口 | 可替换策略、实验配置和完整运行记录 | 在对应对照中观察到收益、失败原因或明确证据不足 |
| 训练联动 | 哪些数据变化转化为目标能力收益 | SFT 或 RL 接口与独立评测回路 | 有支持相应范围结论的下游结果 |
